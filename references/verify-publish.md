# Verify and deliver

Test real assets and motion, music synchronization, keyboard/touch directions, PERFECT/GOOD/MISS, duplicate-hit prevention, pause/resume including countdown, playback rejection recovery, result, restart, mode changes and track/mode record isolation. Run a complete demo; inspect JavaScript/WebGL errors and all chart groups.

Check a desktop and narrow phone viewport plus changed short/landscape layouts. Compare document bounds to viewport, but also check clickable controls and full-body framing. Inspect idle, intro, playing and results. Fix actual failures before claiming a playable delivery.

The starter has no deployment binding. Preserve existing hosting configuration and URL. For Sites, read the currently installed building/hosting instructions and use current native tools rather than a frozen schema. Local-only work stays local. Do not create a replacement site merely to bypass a deployment failure.

Build from the final source and inspect the explicit public-files.json allowlist, static output and library notices. Exclude credentials, private logs, signed links and unrelated assets. Service-call authorization does not itself authorize public asset distribution. Preserve material provenance outside public output.

Resume a pending deployment by its existing ID; report a final URL only after successful completion. Deliver how to play, key changes, actual checks and remaining limitations. A single-file publication example additionally needs all media/dependencies embedded and real offline file-URL testing; the ordinary static build is not that artifact.
